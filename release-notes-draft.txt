Discussion feedback round: lazy relay, streamed 1:1 sends, scoped announcements

Implements the community review from the Holepunch discussion (issue #2):

RELAY IS NOW A FALLBACK, NOT A BEACON
- 'auto' mode no longer connects the relay at boot. It engages when (a)
  pairing intent exists on this device (setPairingIntent — pairing screen
  open; the joiner's registerJoinerCode also starts it), or (b) the swarm
  has run with ZERO peers for 30s — the signature of a challenged network.
  'relay-primary' stays eager; 'direct-only' never starts it.
- Pairing challenges no longer carry the device identity: the relay is
  metadata-untrusted, and the challenge handler never used it. The host's
  response still carries identity (the joiner needs it to build the device
  record) and is only sent to a peer that challenged with the code topic.
- RelayClient buffers sends while the WebSocket is CONNECTING (lazy start
  fired challenges inside the handshake window — they were silently lost)
  and flushes on open, capped and TTL'd.

1:1 FILE SENDS NOW STREAM FROM DISK (zero duplication)
- offerFile() tags sends with source: 'stream'; TransferEngine routes them
  through the same protomux channel machinery folder sync uses. No full
  copy is staged into the exchange store on the sender anymore.
- Core staging remains only for multi-receiver fan-out (drop codes), where
  one staged core serves N receivers.
- Receive side: stream offers skip the coreKey requirement, pre-create the
  stream channel, land in the downloads dir with normal approval flow, and
  progress events report isSync honestly.

WATCH PARTY ANNOUNCEMENTS ARE SCOPED
- Room code stays broadcast (it IS the join capability / discovery), but
  title and host name now only go to PAIRED peers — untrusted peers learn
  a party exists, not who hosts it or what's playing.

test.js: both engines signal pairing intent (mirrors the real app where
the pairing screen is open), so relay timing matches production UX.

Full suite green: 61 unit + 16 e2e matrix + 17 watch party + 23 pairing
backoff + 60/60 live checks (pairing, re-pairing after deletion, drops,
sync).
